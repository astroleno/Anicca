# Anicca `/dialogue` 产品体验独立审阅（2026-10-29）

## 总体判断

- **App 体验**：恢复能力扎实。刷新后，图、焦点、草稿和续写对象都回到原处；全景返回后回到同一段阅读；Esc 能收起阅读并把焦点还给种子。真正的摩擦在屏幕空间分配：320×640 下，阅读首屏只露出约 64px 正文（两行左右），其余位置被标题、理解变化和动作按钮占掉。
- **概念一致性**：图模型本身是一致的，正、反、合、来源、代际都对得上。不一致出在词汇和空间两层：
  - 同一个"生成正反"的操作，界面上有推演正反、裂变、正反裂变、分裂为正与反四种叫法。
  - "视角/角度"同时指相机位置、生成立场，还有"画作视角"这一种生成方式。
  - 舞台上种子在静止状态就互相融合，跟"拖近才出现液桥、才可合成"的视觉语言冲突。
- **心流**：最直接打断"读 → 想 → 写"的是：读完一段，一点下面的输入框，要回应的原文就消失了。其次，等待时说"正与反会在这里落位"，结果却落在别处。

## 范围与证据

**检查过的状态**（本轮截图 01–16 与 `capture-notes.md`，均为新拍）：1280×720 下的空态、输入、等待、正反结果、阅读、角度面板、点击输入框后收起阅读；390×844 下的阅读、组合选择、合的结果、极性选择、全景；320×640 下的继续写、更多菜单、刷新恢复、带草稿浏览其他种子；以及 `reading-geometry.json` 的 DOM 测量。

**读过的源码**：README、flow-continuity 文档，以及 `DialogueShell`、`DialogueComposer`、`SeedGuide`、`SeedPrimaryActions`、`SeedReadingContent`、`SeedInspector`、`SeedPassage`、`SeedMeaning`、`PerspectiveControls/Panel`、`BubbleStage`（相关段落）、`WorkspaceBar`、`EvolutionOverview` 及对应样式，还有 `seeds.ts`、`seedPlacement.ts`、`controller.ts`、`branchGraph.ts`、`platform.ts`。

**本轮没有做的**：拖动合成、长按、多指手势、实体键盘、失败与断网、深色主题、屏幕阅读器、圆桌、分身、一句话追问的真实生成、角度与极性的真实生成。

**证据标注**：
- 【实测】：截图或 capture-notes 中的事实
- 【源码】：读代码可以确定的行为
- 【主观】：设计判断

## 保留得好的设计

- **恢复链完整**【实测】：刷新恢复（14）；浏览其他种子时不改写已有草稿的对象（15）；全景返回回到原阅读（步骤 11）；Esc 收起阅读并把焦点还给种子。
- **等待状态诚实**：显示真实秒数，按时长换文案，可以取消（`DialogueComposer.tsx:120-124`）；等待中的种子幽灵就地显示。
- **错误文案**：说明了什么没有被改动，并保留"重试上次"（`DialogueShell.tsx:197-278`）。重试快照独立于之后的编辑。
- **阅读时舞台设为 inert**，避免误拖（`SeedReadingContent.tsx:65-67`）。
- **组合有列表替代拖动**，并把"本轮另一端"放在首位（`SeedInspector.tsx:186-189`，截图 08）。
- **极性展开先解释、再确认**，不会一点就调用模型（截图 10）。
- **视觉方向保持住了**：浅色、低饱和、阅读不套卡片、文字独立；主要按钮高 44px（capture-notes 第 34 行）；320 宽无横向溢出；阅读进出动画、全景镜头补间与回放都有 reduced-motion 分支。

## A. 已证实的行为缺陷

### D1 · P1 · 点输入框会收起正在读的原文
- **证据**：【实测】capture-notes 第 16 步与截图 16：读「切口未定」时直接点底部文本框，阅读立即收起，回到舞台。
- **原因**【源码】：
  - `SeedReadingContent.tsx:68-72` 规定，阅读层之外的任何 pointerdown 都会关闭阅读。第 69 行只豁免了工作区栏、带 `data-preserve-seed-reading` 的元素和打开的 dialog。
  - 输入框渲染在阅读层之外（`DialogueShell.tsx:2393`），且没有豁免标记。这个标记只出现在 `SeedGuide.tsx:48`、`PerspectiveControls.tsx:36`、`PerspectivePanel.tsx:78`。
  - "继续写"按钮同样会显式关闭阅读（`DialogueShell.tsx:2344`）。
  - 对照：一句话追问已经能在阅读中内联写作（`DialogueShell.tsx:2337`、`SeedPassage.tsx:109`），说明"边读边写"在产品里已有先例。
- **用户影响**：最常见的回应方式是读完一段就在下面写，现在一落笔原文就不见了，只能凭记忆写。这和 flow 文档"从读到写连续"的目标直接冲突。
- **建议**：
  - 输入框加豁免。聚焦时阅读保持打开，阅读区收缩为可滚动区域。
  - 没有草稿时，写作对象跟随正在读的种子（与 `DialogueShell.tsx:1025` 的现有规则一致）。已有指向别处的草稿时，不隐式改写对象（遵守 flow 文档第 36 行）。
  - "继续写"只负责切换对象并聚焦，不关闭阅读。
  - 显式关闭仍然由"返回种子"、Esc、点空白舞台完成。
- **验收**：桌面、390、320 三种宽度下，读一颗种子 → 点输入框 → 输入两行，正文仍可见、可滚动。草稿指向别的种子时，点输入框不改变对象。Esc 行为不变。

### D2 · P2 · 正反没有落在等待时承诺的位置，静止时就互相融合
- **证据**【实测】：
  - 截图 03：等待时正在左下、反在右下，配文是"正与反会在这里落位"。
  - 截图 04：两颗实际都落在左侧，静止时融成一团，右半边留空。
  - 截图 16：正、反、合三颗互相重叠。
  - 截图 12/14（320 宽）：四颗粘成一团，"我总想把一个想法…"的标签离自己的液滴约一个液滴远，压在别的液滴下方。截图 09 中"来源 · 正 痕迹先行"贴在反液滴下方。
- **原因**【源码】：
  - 等待时的位置固定为锚点 ±20%（`BubbleStage.tsx:891-898`），配文在 1067-1069 行。
  - 结果的位置走另一条路：`seeds.ts:118-126` 用模型给出的内容偏向坐标定位，用户没有选任何角度也会生效（118 行只排除了用户节点）；再由 `seedPlacement.ts:25-29` 覆盖初始位。
  - 最小间距是百分比 29/22（`seedPlacement.ts:50`），液滴直径却是 176–216px（`DialogueShell.module.css:3912-3915`）。两者之间没有换算，所以静止状态下会重叠。
  - 04 的具体落点是否由内容偏向坐标造成，是从截图和源码推断的，没有读 DOM 确认。
- **用户影响**：
  - 等待时建立的空间预期落空，结果出来后要重新找。
  - 静止融合看起来像"已经在合"，与 README 第 24、257 行"拖近、液桥增强才表示可合成"的语言冲突。
  - 窄屏下标签归属不清，容易点错种子。
- **建议**：
  - 静止时液滴之间保持至少一个直径的间隙（按像素计算），融合只留给拖动接近。
  - 等待幽灵直接使用最终落点；或者结果到达时，从幽灵位置连续过渡到落点。
  - 用户没有选角度时，内容偏向坐标不驱动位置。如果要保留，就在舞台边缘标出轴端名称，让位置可读。
- **验收**：三种视口下生成正反并组合后，静止时任意两颗液滴边缘不相交；每个标签离自己的液滴最近；幽灵与最终位置的偏差小于半个直径，或者有连续过渡。

### D3 · P2 · "下一次生成就从这里展开"只对部分种子成立
- **证据**：【源码】可以确定，【未实测】（capture-notes 第 28 行：角度面板只打开过，没有完成生成）。
- **具体行为**【源码】：
  - 角度面板写的是"选一端，下一次生成就从这里展开"（`PerspectivePanel.tsx:105`）。
  - 舞台上的"推演正反"会优先使用种子创建时记录的角度（`DialogueShell.tsx:2263-2266`），阅读中也默认用它（`SeedInspector.tsx:100-101`）。"改用当前角度"只在阅读里出现（130-134 行）。
  - 只有裂变产生的正反会记录角度（`controller.ts:94`、`branchGraph.ts:191-192`），从输入框生成的正反不记录（`controller.ts:64-67`）。
  - 组合和输入框生成用的是当前全局角度（`DialogueShell.tsx:1721`、1307）。
- **用户影响**：两颗同样标着"正"的种子，一颗跟随新设的角度，一颗不跟随，舞台上没有任何区分。面板文案的承诺对一部分种子是假的。
- **建议**：先定一条全局规则。推荐：新设的角度对下一次任何生成都生效，种子原来的角度作为"沿用原角度"的可选项。规则定下前，舞台操作行至少要像阅读中那样提示"从「…」展开 · 改用当前"。
- **验收**：设为"细节"后，分别对输入框产生的正、裂变产生的正点舞台上的"推演正反"，两次请求的角度一致；或者界面明确显示差异，并可以切换。

### D4 · P2 · 窄屏全景默认就聚合，4 个想法的图也看不清来路
- **证据**【实测】：截图 11（390×844，4 个想法）默认显示一个"2 个想法"簇，位置在第 0 代与第 1 代之间，起点和「痕迹先行」被合并成一团。详情摘要被底栏截断，"进入种子"不在首屏。
- **原因**【源码】：
  - 缩放比例小于 .78 时就聚合并隐藏说明（`EvolutionOverview.tsx:193`、226）。
  - 自适应缩放按每代 220px 计算（152 行），手机宽度下约为 .47，所以手机上任何 3 代以上的图默认都会聚合。
  - 簇按屏幕网格分桶（197 行），会跨代合并。
  - 窄屏详情区只占 34% 高度（`EvolutionOverview.module.css:65-67`）。
  - 可以恢复：点簇会放大两倍（329 行），也有 ± 按钮。
- **用户影响**：手机上全景的主要用途"回看来路"在默认视图里看不出代际关系。
- **建议**：小图（例如 30 个节点以内）不聚合。窄屏改为纵向排代，或允许横向滚动。聚合只留给大图（与 325 行已有的 >120 条件一致）。"进入种子"放在详情区顶部。
- **验收**：390×844 打开 4 节点全景，四颗都有名字和类型，代列对齐，"进入种子"在首屏可点。

## B. 设计改进

### U1 · P1 · 阅读区把正文挤到动作之后，窄屏首屏几乎读不到
- **证据**：
  - 【实测】`reading-geometry.json`（320×640）：正文从 y=387 开始，滚动区底部 y=451，首屏正文约 64px。正文之前的 237px 被标题、理解变化、三个按钮和"选一句追问"占用。滚动区底部到输入区顶部还空着 72px（451→523）。
  - 【实测】截图 07（390×844）首屏正文约 9 行，截图 05（1280×720）约 5 行（视觉估计）。
  - 【源码】渲染顺序是理解变化 → 生成动作 → 选句入口 → 正文（`SeedInspector.tsx:213-218`、`SeedPassage.tsx:98-99`）；有写作对象时，阅读层底部固定多预留 96px（`DialogueShell.module.css:4159`，默认为 4015 行的 52px）。
- **用户影响**【主观】：读者先看到"下一步做什么"，后看到正文，等于鼓励没读完就推演。320 宽下几乎没法读。
- **建议**：在现有方向内调整：
  - 把三项生成动作与"继续写/分身"合并成一行，放在正文之后，或贴在阅读区底部。
  - "选一句追问"缩小为正文旁的入口。
  - 窄屏下"理解变化"默认截断为一行，点开再展开。
  - 底部预留按写作对象行的实际高度计算，不用常量。
  - 这一项和 D1 一起做：输入框聚焦时阅读区还会再缩，必须一起量。
- **验收**：首屏正文 320×640 至少 6 行，390×844 至少 12 行，1280×720 至少 8 行。主要动作不滚动、或一次滚动以内可达。真机键盘展开时正文至少保留 3 行。

### U2 · P2 · 同一操作有多个名字，"视角/角度"一词多义
- **证据**【源码 + 实测】：

| 操作 | 界面上的叫法 |
|---|---|
| 生成正反 | 推演正反（`SeedPrimaryActions.tsx:12`）、裂变（`SeedGuide.tsx:11`、`EvolutionOverview.tsx:227`）、正反裂变（`DialogueShell.tsx:2278`、`EvolutionOverview.tsx:343`）、分裂为正与反（`BubbleStage.tsx:273`） |
| 沿维度两端 | 极性分裂（`SeedPrimaryActions.tsx:14`）、沿极性展开（`SeedInspector.tsx:179`）、极性展开（`EvolutionOverview.tsx:343`）、极性视角（`SeedInspector.tsx:163`） |
| 合成 | 组合、让想法相遇、合、合流、收束、新的联系 |
| 视角/角度 | 换个角度（同时设定生成立场并转动相机，`PerspectivePanel.tsx:39-42`）、思考空间、只转动视角、拖动空白转动视角、画作视角（另一种生成，`DialogueShell.tsx:2150`） |
| 返回 | "返回种子"在阅读中是关闭阅读（`SeedInspector.tsx:165`），在全景里是回到原阅读（`EvolutionOverview.tsx:335`） |

  - 合流结果上的"继续展开"按钮实际只是打开阅读（`DialogueShell.tsx:2297`）。
  - 全景页脚需要专门解释"极性是观察角度，正反是推演方式"（`EvolutionOverview.tsx:407`），说明这层区分界面本身没有表达出来。
- **用户影响**：从按钮名推不出它会不会调用模型、会多出几颗种子。指南提到"裂变"，屏幕上却没有叫这个名字的按钮。
- **建议**：建一张小词表，只改文案，不改流程：
  - 名词：种子（界面对象）；想法（只指用户写的那一颗）。
  - 动词：推演正反 / 沿维度展开 / 组合 / 追问。
  - 结果：正 · 反 · 合。
  - "视角"只指相机，"角度"只指生成立场。
  - "继续展开"改为"阅读合"。
  - 指南、空态、全景筛选、状态播报统一使用这张表。
- **验收**：用户可见字符串中，每个操作只有一个动词；新用户看过一次按钮，能说出"组合"之后会多出一颗种子。

### U3 · P2 · 屏幕上同时有两个"当前对象"，窄屏还看不出操作作用于谁
- **证据**：
  - 【实测】截图 16：舞台操作行左侧显示「切口未定」，下方紧挨着"基于「可辨切口」"，两个指向不同种子的对象并列。
  - 【源码】390/320 宽下，操作行的种子名被隐藏（`DialogueShell.module.css:4309`），截图 09/10 底部只剩三个动词。
  - 【源码】生成或组合完成后，写作对象被静默重置为根（`DialogueShell.tsx:1372`、1838）；根对象的提示行被视觉隐藏（`DialogueShell.module.css:3999`），只剩占位符"写下一个想法…"能区分（截图 09 底部）。
- **用户影响**：看着刚出来的"合"在输入框里写，会写成一颗与它无关的新根。手机上点"推演正反"前，无法确认它作用于哪颗种子。
- **建议**：保留阅读对象与写作对象分离（flow 文档已确认），但让两行可辨：
  - 操作行写成"对「切口未定」："。
  - 写作行始终可见，包括"独立的新想法"这种根状态。
  - 窄屏保留截断后的种子名。
- **验收**：320×640 下，任意时刻都能同时看出操作对象和写作对象；生成完成后，底部明确写出对象。

### U4 · P3 · "更多"菜单层级不利于长期使用
- **证据**：
  - 【实测】截图 13（320×640）：首屏是工作区操作、外观、想法。
  - 【源码】"最近工作区"渲染在所有附加分组之后（`WorkspaceBar.tsx:203-221`），排在"液体渲染对照""显示氛围背景""视觉实验"之后（`DialogueShell.tsx:2159-2181`），需要滚动才能看到。
  - 【源码】舞台上不显示当前工作区名（`DialogueShell.module.css:3884`）。
  - 【源码】"画作视角"没有说明，只在有草稿时可用，会生成第四类节点（`DialogueShell.tsx:2149-2150`、1462）。
- **建议**：
  - 最近工作区并入"工作区"分组。
  - 渲染对照移到 labs 或调试参数下。
  - "画作视角"加一行说明，或移出主菜单。
  - 字标旁用小字显示当前工作区名，保持留白。
- **验收**：320×640 打开"更多"，首屏可见当前工作区名和至少两个最近工作区。

### U5 · P3 · 打开或关闭阅读时，舞台整体跳位
- **证据**：
  - 【实测】从截图 04 到 05，三颗液滴和标签整体下移约 30–60px（截图对比估计）。
  - 【源码】有舞台操作行时，舞台底部多让出 140px（`DialogueShell.module.css:4292`）；阅读时操作行不渲染（`DialogueShell.tsx:2259`），视口变高，种子按百分比坐标重新投影。关闭阅读时反向跳回。
- **用户影响**：每读完一颗返回，舞台都会轻微跳一下，削弱空间记忆。
- **建议**：舞台视口高度不随操作行显隐变化，让操作行浮在舞台之上。
- **验收**：开关阅读前后，同一种子的屏幕位移小于 4px。

### U6 · P3 · 桌面单击有延迟，双击会直接调用模型
- **证据**【源码】：
  - 单击要等 260ms 才打开阅读（`BubbleStage.tsx:876-878`），用来区分双击。
  - 双击直接发起"推演正反"（1201-1205 行）。
  - 舞台提示只写了"拖动空白，转动视角"（`platform.ts:9`）。
- **用户影响**【主观】：最常用的"点开读"每次都有可感知的延迟。误双击会新增两颗种子：等待中可以取消，但没有撤回。
