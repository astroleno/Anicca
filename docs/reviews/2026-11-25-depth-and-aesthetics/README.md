## 对既有设计的判断

原评审的视觉判断是：桌面合流构图偏右，均匀柔边使液滴体积感偏弱；320 宽图里的“来源 · 正”跨到邻近液滴上。复查时直接问读者能否认出焦点、找到两颗来源，并一次点中想读的种子。旧图之后已有标签与触点对齐（`015d084`）、阅读卫星可达（`49845c6`）、键盘上方空间（`2d3febd`）以及延迟渲染与静止降耗等变更。[桌面旧图](./evidence/2026-11-19-desktop-synthesis.png) · [320 宽旧图](./evidence/2026-11-19-mobile-320-synthesis.png)

- **舞台与阅读**：布局已有标签测量与避让；液体已有角色色族和深度值。仍可研究材质、谱系混色、灰度层次与焦点体量，先通过遮住标题后能否定位焦点、恢复标题后能否读清关系来判断。阅读态保留「推演正反」「组合」「沿极性展开」三项同级基本操作。
- **性能**：已有自适应分辨率、空闲降帧、减少动态效果与平面降级。浏览器截图可查布局和状态，iOS Safari、微信内置浏览器及中端安卓的交互帧耗需实机测量。本轮没有相应真机数据；CSS 模糊声明的数量不足以估算一次交互的成本。

- **颜色与层次**。已有正暖、反冷、合灰绿的角色色族，空种子呼吸为 6.4 秒；旧式琥珀光晕 `.stageGlowSecondary` 已隐藏。多个来源对可以产生相近的混色，用户靠位置及可打开的关系确认具体来源。[角色色族](https://github.com/astroleno/Anicca/blob/0fce3c5/src/components/dialogue/liquid/color.ts#L67) · [呼吸](https://github.com/astroleno/Anicca/blob/0fce3c5/src/components/dialogue/DialogueShell.module.css#L3877) · [光晕的生效规则](https://github.com/astroleno/Anicca/blob/0fce3c5/src/components/dialogue/DialogueShell.module.css#L3979)

## 保留供讨论的方向

| 方向 | 需要先弄清的问题 |
|---|---|
| P1 合的结局与正文 | 怎样验证保留、舍弃和提升，何时适合选择一方或暂不融合？用什么最终结果驱动反馈？ |
| P2 材质与色族 | 在已有色族、深度与低彩度基础上，怎样靠体量和材质改善辨识？是否需要调整琥珀色、字号或缓动？ |
| P3 时间与纵深 | 代数与重访时间表达不同含义；淡化、下沉与“全部浮起”是否帮助用户找回思路？ |
| P4 他人与盲区 | 邀请与导入如何取得真实视角、保留来源并让用户决定落点？ |

上述方向以及流式标签、触感、极性拖动、遗留 prompt 清理和性能预算均留作研究。沿用轻盈、低彩度、少解释文字的设计取向，避免增加横向入口或给思考打分。

### 可试验的细节

- **构图与材质**。先试焦点、直接来源、远景约 1∶0.7∶0.45 的体量差。用稍密的内核、柔边、顶部微光和底部阴影试出“芯实边虚”的体积感。正偏透、反偏浓，合可试双色内核；焦点身份要能独立于正反身份改变。以灰度图检查层次，再恢复颜色观察谱系。
- **等待与改写**。分支生成可以试着在正文前展示流出的短标签；高风险合成可能经过审计与改写，抢先展示的摘要可能与最终正文不符。用一次正常生成和一次触发改写的样例，观察从初稿到定稿是否让用户误读。
- **纵深与重访**。同一条思路推演了几代，可试用密度或纵向位置表达；距上次阅读多久，可另试淡化与重访时浮起。比较“刚读过的深层想法”和“久未重访的第一颗种子”，检查两种含义能否区分，并确认“全部浮起”仍能找回旧想法。

## 第六轮 · 普通舞台与合的淡紫配色

基线 `61de19e`，320 宽，退出合流后的五颗液滴直径集中在 67–70 px。焦点是「水边活动」，其父「早期共同问题」与两个直接子「调整水边」「照料土地」应居第二档，隔一代的合「共同改写约定」居远景。普通舞台上多数非焦点被标成 child，现有角色无法表达这组关系。在同一场景实点左下「未知区」文字中心，会打开起点种子。上轮已验收的合流标签和象限恢复是本轮回归基线。

用户选定淡紫方案。两个来源的 OKLCH 明度、彩度都取算术平均，有色来源沿短弧取色相中点，一方近灰时沿用有色一方的色相。第五轮候选图采用较高彩度，仅记录当时的比较。本轮须以实际默认配色重拍。分批执行与独立验收见[第六轮计划](./plan.md#第六轮--普通舞台与合的淡紫配色)。

## 第七轮 · 正反合正文
