# 口述史复盘：审校检查了原声，漏掉了网页上的文字

第三候选 `ee26984` 在正式回归题 `holdout-06` 返回 HTTP 200，正文建议首页保留文字摘引或转述。受访者只同意馆内播放原声。首页想留住第一人称证言是策展方的愿望；原文没有授予面向网页访客以文字使用证言的许可。去掉声音、标明处理都无法补足这项许可。请求耗时 12,732 毫秒，仅一次 HTTP 尝试。[请求、原文与最终交付](./after/responses/holdout-06-synthesis.json)

## 实际审校链条

下表取自请求 `r9-after-holdout-06-1`，只列该请求留存的校正与审校阶段。[逐阶段原始回包](./after/authorization-reviews.json)

| 阶段 | 模型与接口实际所做的事 |
|---|---|
| 校正稿 | 正文直接建议“首页可保留文字摘引或转述”。盘点列了原声上网、文件可下载转发、另获网页许可三项，遗漏这句正在建议的公开文字使用。 |
| 首次审校 | 回包给出通过，三行分别填暂缓、暂缓、有条件执行。没有一行检查首页摘引。程序记录缺少能证明暂缓或条件的正文引文，要求同文补证。 |
| 同文补证 | 仍只有三行。最后一行以正文 R6 作为另获许可的依据，缺项填空。程序记录未核实授权依据和缺少条件，转入一次实质改写。触发改写的问题仍集中在原声外发的条件。 |
| 改写 | 正文明确了今晚不向开放网站发布原声，馆内原声照旧，仍建议“首页保留文字摘引或转述”。新盘点只列“网页发布后文件可被访客下载、转发”。 |
| 独立复审与交付 | 回包只有两行，均标 F1。第一行按 R4、B1 暂缓原声上网，第二行按 R5、U2 放行馆内原声。两项判断各有依据，首页面向公众的文字使用仍没有审校行。程序接受通过，正文、摘要和 change 均保留了公开文字使用的结论。 |

因此，这次失败发生在动作覆盖上。程序实际执行了补证、改写和复审；两行正确的原声判断一起通过，却不能为另一种形式和受众提供依据。

## 卷外开发镜像 dev9

两次卷外请求均来自正式候选 `ee26984`。以下按实际模型回包核对末稿，再按 HTTP 响应核对交付。两稿在授权范围上都已给出正确动作，用户均只收到 502。这两次诊断单列，不计入正式卷。[开发正反例完整回包](./development-oral-final.json) · [请求及交付记录，draw 9](./development-controls.json)

**只有馆内原声许可。** 校正稿建议“首页改用经家属确认的摘引或转述”。第一次实质审校正确指出家属能辨认声音并不赋予代理权，触发改写。末稿明确原声不上网页、馆内播放照旧，也明确“在查明这层授权前，今晚不采用该形式”，首页只用不涉她原话的说明文字。它同时守住了网页原声和文字摘引两项边界，没有转而假定家属可以代签。

改写后审校两次都给出通过。第一次为文字动作引用正文 R3 作为权利依据，接口因此记录一次依据未核实及两处条件未定位；补证将两个动作都列为暂缓、均引 B1，仍未通过两处条件核验。B1 说明馆内原声的许可边界，暂缓决定则在正文中明确写出。此时唯一一次实质改写已经用掉，接口以 `synthesis prose could not be verified` 返回 502。该次失败发生在已纠正正文的复审交接。

**明确允许首页文字引语。** 权利人亲自更新了许可，用途为介绍旧市场搬迁，形式为特定一句文字引语，受众为开放网站首页访客，条件是标明出自展厅口述。校正稿落实了“首页放获准引语、标注出处，录音留在展厅”，并明确“原声不进公开版”。该稿因字数不足补段，新增文字再次限定了许可的载体和渠道，生成合同通过。

两次审校都认可正文，把允许的首页引语列为 F1，以用户更新 U6 为依据；把原声上网列为 F2，以 U7 的馆内限制为依据。F1 引 R4，同一句还说录音留在展厅；F2 引 R3，正文在该句明确写明原声不进公开版。接口两次均记录 `authorization_action_too_broad` 和 `missing_authorization_gate`，最后以 `reviewer_protocol_error` 返回 502。权利人已经授权、正文已经正确分开两种使用，判定仍未转化为可读交付。

## 代码边界与技术判断

另外两条是静态可达风险，未在上表正式请求中观察到。审校可用 `not_adopted`、一个能定位的正文片段和非空理由解除未定位的动作，程序没有核实片段确实排除了该动作。另一处判断核对来源归属与部分形式、受众差异，但同形式同受众下的用途变化仍依赖审校报告的缺项。不能据此给其他题推定判词。[冻结代码：动作处置](https://github.com/astroleno/Anicca/blob/ee26984/src/features/dialectic/server/meaningReview.ts#L333) · [冻结代码：范围核验](https://github.com/astroleno/Anicca/blob/ee26984/src/features/dialectic/server/meaningReview.ts#L396)

**技术判断。** 应把独立的动作盘点建在最终交付正文上：先按正文位置列全建议的使用动作，再由独立审校逐项标明权利人原句覆盖的用途、形式与受众。每次改写后重新盘点；未匹配到授权的具体动作进入定向改写，明确有据的同句动作保留。这样才能检验漏掉的“首页文字”本身，继续增加原声、网站或摘引的触发词无法证明动作已查全。
