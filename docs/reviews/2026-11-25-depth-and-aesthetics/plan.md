# 分批执行与验收

每批只暂存该批文件。Sol 实现，Astra 对照下表独立验收；按已授权的批次提交、推送。若复查发现某个旧问题已经消失，记录当前版本、场景与通过依据，保留有回归价值的验证即可。

| 批次 | 模块与接口 | 验收与验证 |
|---|---|---|
| 1　校准评审 | 本目录的评审和计划。区分旧截图、当前代码、检索复现与待测真机表现 | 核对旧证据的提交号、摘要与呼吸时长、审计路线含义、暂不融合交互以及基本操作约束。独立提交两份文档 |
| 2　窄屏焦点与双来源 | 通过正常思考流程生成合，在 `BubbleStage.tsx`、`labelLayout.ts` 和相关样式中定位实际问题。保留图节点 ID、两个父节点及阅读返回关系。按需扩展 `scripts/visual-smoke/thought-flow.mjs` 及相应组件或布局测试 | 当前版本先取稳定画面。320×568 下焦点、两个来源可辨认，相关标签互不遮挡，也不挡住另一颗的点击区域。逐一操作两来源，核对各自标题或节点 ID，返回后仍可操作另一颗；同时验证阅读态三项基本操作可见可用。390×844、1440×900 复查布局。运行相关测试与对应视觉冒烟，记录视口、提交及结果 |
| 3　策略卡语境 | 修改 `src/features/dialectic/server/policyCards.ts` 的 `retrieveDialecticPolicyCards(input)` 检索规则，维持卡片列表、排序、上限及 `isHighRiskDialectic(cards)` 接口；在同目录 `policyCards.test.ts` 添加反例和成对正例 | 两句已知个人问题均返回空列表且不触发高风险；近义个人表达也能通过。明确讨论缓存权限隔离、执行时间预算的输入仍命中对应卡，高风险正例保留原风险分类。运行策略卡及受影响的合成测试，完成仓库常规检查 |

## 视觉证据的读法

先等阅读或合流动画结束，再检查几何关系与截图；通过页面实际点击验证命中目标。冒烟中的固定接口数据可复现相同图结构。记录浏览器与视口，能取得真机证据时另记设备、浏览器和复现操作。若只有浏览器数据，真机性能继续标为待测。此次不以旧截图或模糊层数量作为修改材质、动效、性能预算的依据。
