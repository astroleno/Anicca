## 结论

产品已经形成了清楚的视觉语言：软糯种子负责呈现想法，阅读内容直接融入同一舞台，选句追问也留在原文。无需增加卡片或重做视觉。下一轮最值得处理的是**探索后的回到原位、维度编辑中的草稿保护，以及组合操作的可预期性**，它们决定用户能否放心试探，而不必持续照看界面状态。

本报告给出 5 项：2 项源码与本轮浏览器复现共同确认的 P2 行为问题、1 项 P2 启发式风险、1 项已复现的 P3 状态文案问题、1 项 P3 待验证假设。没有发现足以据本轮证据判为 P1 的问题。优先级指对主要体验的影响，不代表已经观察到真实用户受阻。

## 值得保留

1. **阅读与舞台同属一个空间。** 中央正文、降弱的背景种子和明确的「返回种子」维持了探索对象的连续性；来源和正文无需拆成卡片。[移动阅读截图](evidence/baseline/thought-flow-live-mobile-390-response.png)，[阅读实现](../../../src/components/dialogue/SeedReadingContent.tsx#L6)，[背景弱化样式](../../../src/components/dialogue/DialogueShell.module.css#L4025)。
2. **选句追问保留了句子和上下文。** 引文、输入、追问动作在原文位置，避免用户把问题重新搬到另一张面板；精确偏移也避免重复句子选错来源。[移动选句截图](evidence/baseline/thought-flow-live-mobile-390-inline-question.png)，[选句实现](../../../src/components/dialogue/SeedPassage.tsx#L60)。
3. **极性两端和辩证正反已经在语言上区分。** 「换观察位置，看见两端」与「推进判断，检验前提」承担不同任务；极性选择页明确说明两端都能继续推演正反。[极性选择截图](evidence/baseline/thought-flow-live-mobile-390-axis.png)，[动作说明](../../../src/components/dialogue/SeedInspector.tsx#L95)，[两端说明](../../../src/components/dialogue/SeedInspector.tsx#L115)。
4. **观察框架保留历史，乔哈里保留不确定性。** 每颗种子沿用原框架，切换当前框架是显式动作；self-report 维度作为待确认的假设入口，提示词也约束不得凭空推断知晓状态。[框架切换](../../../src/components/dialogue/SeedInspector.tsx#L101)，[乔哈里假设说明](../../../src/components/dialogue/SeedInspector.tsx#L117)，[提示词边界](../../../src/features/perspectives/model.ts#L157)。这能防止「AI 解释」被误当成用户心理事实。
5. **合成没有抹掉来源，也没有强制得出新结论。** 合后保留来源入口，无法合理联结时可以暂存相遇、补充联系或分别继续。[桌面合后截图](evidence/baseline/thought-flow-live-desktop-synthesis.png)，[来源入口](../../../src/components/dialogue/SeedInspector.tsx#L180)，[暂不融合](../../../src/components/dialogue/SeedMeaning.tsx#L28)。
6. **等待和失败没有占领整个舞台。** 用户可继续写、取消、保留草稿后重试；错误说明当前图与圆桌未被改动。这样的局部反馈比全屏等待更利于思路不中断。[移动失败场景，受控响应](evidence/baseline/mobile-failure-retry.png)，[等待及重试实现](../../../src/components/dialogue/DialogueComposer.tsx#L119)。

## Findings：已证实的行为与状态问题

### L-01 · P2 · 移动端隐藏了视角复位，探索后缺少轻量回到原位的入口

- **触发流程：** 390px 移动视口出现种子后，在空白处连续单指平移，或双指放大并转动，再尝试回到最初的构图。
- **可确定的事实：** 唯一同时重置旋转、pan 和 zoom 的 `resetView` 绑定在 `.spaceControls` 内，而该容器在宽度不超过 640px 时整体隐藏。单指 pan 累加位移，没有可见边界；「换个角度」中的前、后等按钮只改旋转，不清除 pan 或 zoom。
- **主线程本轮复现：** 390px 移动触摸上下文以 CDP 执行三次空白处单指平移，pan 从 `(0, 0)` 变成 `(-840, -210)`，种子全部移出视野；复位不可见。随后点击「从前方观察」和「按已有角度归位」，pan 仍为 `(-840, -210)`。这是触摸视口模拟，不能视为真机手感测量。
- **用户影响：** 用户可以自由探索，却不能用等价的轻动作回到原位。将想法拖出视野后，只能自己反向寻找，或依赖刷新；这打断心流，也降低继续尝试手势的信心。这里没有断言手势失效或性能不达标。
- **证据：** [正常移动舞台](evidence/baseline/thought-flow-live-mobile-390-after-polarity.png)、[平移后舞台](evidence/fresh/mobile-390-panned-stage.png)、[归位后仍为空白](evidence/fresh/mobile-390-panned-after-arrange.png)、[本轮数值记录](evidence/fresh/observations.json)；[复位函数](../../../src/components/dialogue/BubbleStage.tsx#L460)，[无边界 pan](../../../src/components/dialogue/BubbleStage.tsx#L677)，[前后视角仅改旋转](../../../src/components/dialogue/BubbleStage.tsx#L489)，[复位按钮位置](../../../src/components/dialogue/BubbleStage.tsx#L934)，[移动端隐藏容器](../../../src/components/dialogue/DialogueShell.module.css#L3969)。
- **最小改进：** 保留当前手势，把同一个「复位视角」动作放到移动端可达的位置，例如更多菜单或「换个角度」的纯视角区域；仅在视图改变后出现即可。复位不重排用户拖放的种子，不改思考维度。
- **验收：** 移动触摸视口执行 pan、旋转、缩放后，一次可见动作将临时 pan 归零、zoom 归一、旋转归默认；种子内容、已保存的位置和当前框架不变。浅深色都可读，点击区域至少沿用现有 44px 控件规格。
- **置信度：高。** 源码与主线程本轮模拟触摸复现相互印证；真实用户迷失频率尚未测量。

### L-02 · P2 · 维度编辑草稿会被普通关闭或切换观察静默丢弃

- **触发流程：** 换个角度 → 编辑维度 → 修改名称或某一端 → 点击「观察」，再回到编辑；或按关闭、Escape / 点击外部后重新进入。
- **可确定的事实：** 修改仅保存在面板的局部 `draft`；返回编辑时重新以已保存的 `space` 覆盖，面板关闭时直接卸载。所有这些退出路径都不检查是否有未保存修改，也没有在稍后恢复草稿。
- **主线程本轮复现：** 桌面与移动端都将「尺度」改成「临时未保存名称」，随后切到观察、再回编辑；名称均恢复为「尺度」，提示数量为 0。本轮实际验证的是模式往返丢失；关闭再重开的结论另由组件卸载路径确定。
- **用户影响：** 自定义维度本身就是思考成果。用户为了查看空间或核对另一端暂时离开，却会损失刚写好的概念表述；这比一般设置丢失更直接地打断思路。「取消编辑」可以明确放弃，但普通切换与关闭目前承担了相同副作用。
- **证据：** [移动端未保存名称](evidence/fresh/mobile-390-dimension-unsaved.png)、[模式往返后名称](evidence/fresh/mobile-390-dimension-after-tab-roundtrip.png)、[双端记录](evidence/fresh/observations.json)；[局部草稿状态](../../../src/components/dialogue/PerspectivePanel.tsx#L18)，[关闭与切换入口](../../../src/components/dialogue/PerspectivePanel.tsx#L70)，[返回编辑时覆盖草稿](../../../src/components/dialogue/PerspectivePanel.tsx#L77)，[显式取消与保存](../../../src/components/dialogue/PerspectivePanel.tsx#L95)，[关闭即卸载](../../../src/components/dialogue/PerspectiveControls.tsx#L29)。
- **最小改进：** 保留当前面板与两个模式；有修改时，在本次工作区会话中暂存编辑草稿，普通观察/关闭不丢弃。显式「取消编辑」再放弃草稿。也可用轻量的放弃确认，但不要给每次退出增加确认。
- **验收：** 未保存修改经过观察→编辑、关闭→重开仍能恢复；保存后观察和生成使用新维度；明确取消后恢复已保存版本；切换工作区不把前一工作区草稿带入后一工作区。原本没有修改的关闭依旧直接生效。
- **置信度：高。** 状态生命周期与主线程本轮双端复现一致；本轮审阅者未亲手操作浏览器。

### L-03 · P3 · 组合搜索无匹配时，空态把过滤失败说成没有种子

- **触发流程：** 已经有多颗种子 → 打开组合 → 输入一个不匹配标题或正文的查询。
- **可确定的事实：** `candidates` 同时承担「全部可组合对象」和「匹配查询的对象」；当查询过滤为空时，提示固定为「还没有可组合的种子。可以先写一个想法，或裂变当前种子。」
- **主线程本轮复现：** 使用包含其他种子的固定图，在桌面与移动端搜索「绝对不存在的查询词」，两端均出现上述没有种子的提示；未发起模型请求。
- **用户影响：** 图中明明已有想法，界面却建议重新生成。用户会误以为原种子不能参与组合，或为了清空搜索离开当前思路。
- **证据：** [正常组合选择布局](evidence/baseline/thought-flow-live-mobile-390-pair-after-refresh.png)、[移动无匹配结果](evidence/fresh/mobile-390-combine-no-search-results.png)、[桌面无匹配结果](evidence/fresh/desktop-combine-no-search-results.png)；[查询过滤](../../../src/components/dialogue/SeedInspector.tsx#L83)，[未区分的空态](../../../src/components/dialogue/SeedInspector.tsx#L149)。
- **最小改进：** 区分「本来没有其他想法」和「有想法但查询未匹配」。后者就地显示「没有找到匹配的想法」及「清空搜索」，保留当前来源和查询输入。
- **验收：** 有候选但搜索无结果时不建议生成新种子；清空搜索立即恢复原列表；确实只有一颗种子时，仍提示可先展开或写新想法；不发送模型请求、不改变图。
- **置信度：高。** 分支、文案与主线程本轮双端复现一致。

## Findings：启发式风险，需用任务观察确认影响

### L-04 · P2 · 组合候选看起来可供浏览，实际点选就发起合成

- **触发流程：** 阅读一颗种子 → 点击「组合」 → 在「让想法相遇」列表里查看只有短标题的其他种子 → 点某个标题。
- **可确定的事实：** 候选行只显示极性/角色和短标题，没有摘要或行内动作文字；所有候选的 `onPick` 在组合模式下会立即调用合成。没有供用户先核对候选正文的轻量路径。
- **风险与影响：** 同一产品里，舞台点标题意味着阅读；组合列表中点标题意味着执行。短标题接近或跨度较远的想法，用户可能只是想确认内容，却已启动一次生成。此处属于对动作预期的启发式判断，**没有观察到真实误触数据**；不是要求增加二次确认流程。
- **证据：** [移动组合列表](evidence/baseline/thought-flow-live-mobile-390-pair-after-refresh.png)，[桌面组合列表](evidence/baseline/thought-flow-live-desktop-pair-after-refresh.png)；[候选行](../../../src/components/dialogue/SeedInspector.tsx#L138)，[点击即执行合成](../../../src/components/dialogue/DialogueShell.tsx#L954)。
- **最小改进：** 保持无卡片的文字列表，在列表前说明「选择一个想法，与当前想法合成」，并让候选行的可访问名称和可见动作语义一致。对于仅凭标题难判断的候选，可加入轻量展开摘要/回看正文入口，与合成动作明确区分；不要求所有合成都再确认一次。
- **验收：** 首次使用者在点选前能说出「点这里会合成」；可核对另一个想法而不发请求；两个操作不会相互误触；保留当前来源、搜索条件和本轮另一端优先顺序。建议用 5 位目标用户的短任务观察判断是否保留 P2。
- **置信度：中。** 执行行为证据强；用户是否已经从组合上下文正确推断其含义，尚未实测。

## Finding：待验证的心流假设

### L-05 · P3 · 阅读的第一屏先要求选择下一步，可能削弱理解后再展开的节奏

- **触发流程：** 从一次追问或推演结果打开阅读，尤其在移动端、长标题或带理解变化提示时。
- **观察：** 当前顺序是标题/出处 → 理解变化 → 「推演正反／看极性两端」 → 「选一句追问」 → 正文。现有移动截图中，正文从约屏幕中部才开始，而前面的两个下一步入口具有几乎同等权重。
- **假设与影响：** 对尚未理解当前内容的初次用户，先出现分叉可能引出「现在就得选方向」的决策感。熟悉用户则可能恰好需要快捷继续，因此这不是仅凭截图可判定的错误，也不应据此强制阅读或隐藏快捷操作。
- **证据：** [移动追问结果阅读](evidence/baseline/thought-flow-live-mobile-390-response.png)；[续展控件位于正文之前](../../../src/components/dialogue/SeedInspector.tsx#L164)，[两入口同等布局](../../../src/components/dialogue/DialogueShell.module.css#L4040)。
- **最小验证与改进方向：** 先观察首次用户是否真的先读正文，能否说出新理解后再选择下一步。如果频繁跳过正文又返回，可只调整阅读顺序或降低续展区的初始视觉权重，保持两个动作可直达，不增加卡片或教程。
- **验收：** 用相同想法和等长正文比较当前顺序与调整顺序；记录能复述当前想法、正确区分极性/正反、完成一次继续展开的人数及回退次数。阅读时间更短本身不算成功，连续生成次数更多也不算更有启发。
- **置信度：中低。** 布局事实明确，认知影响是待验证假设。

## 心流与概念一致性的建议验收

沿「初访 → 想法 → 阅读 → 精确选句追问 → 极性两端 → 两端内推演正反 → 任意两来源合 → 刷新 → 从合继续」做一轮桌面和一轮移动任务观察。每个阶段只核对四件事：用户能否指出当前对象、下一步会做什么、如何回到之前的位置、新结果与原来源的关系。不要只用网络成功或图节点增加判为 UX 通过。

保留以下边界作为验收的不变量：无卡片；低饱和软糯材质；桌面 TSL 自动、移动原版及可切换/回退；空白单指 pan、球体直接拖动、双指旋转与缩放分离；乔哈里为假设入口；合不覆盖来源；两个极性端都可以推演正反。
