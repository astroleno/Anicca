## 结论

**视觉语言与核心概念主线已经一致；下一轮应优先改善试探后的恢复能力和阅读连续性。** 低饱和软糯种子、直接融入舞台的正文、贴着原句的追问，以及合后继续展开，形成了安静、连贯的探索方式，值得保留。

独立报告合并、去重并经主线程复现后，建议处理 **4 项 P2、2 项 P3**。另有两项需要真人任务观察的体验假设，单独保留。没有本轮证据支持的 P1，也不建议据此增加卡片、复杂教程或常驻仪表盘。

## UI/UX、概念一致性与沉浸感

| 维度 | 本轮判断 | 理由与边界 |
| --- | --- | --- |
| 视觉氛围 | 一致，保留 | 种子材质、低饱和色相、文学字体与无卡片正文相互配合；阅读时背景降弱，没有持续争夺注意力。 |
| 概念语法 | 主线清楚 | 极性是换观察位置，正反是推进判断与检验前提，合保留双来源并开启后续展开。未发现必须重构这条概念链的证据。 |
| 阅读连续性 | 有恢复缺口 | 同会话返回阅读已有读位保护；刷新仍退出阅读并丢失段落位置，高频键盘开读还会重复空间入场。 |
| 自由试探 | 需要更可逆 | 移动端可把场景移出视野，却没有可见的完整复位入口；自定义维度草稿会在普通切换中丢失。 |
| 思维启发与真实心流 | 不能由本轮直接证明 | 入口、来源与假设边界能支持思考；是否产生新理解、能否长时间沉浸，需要真人读写任务，不能用节点数、截图或网络成功代替。 |

### 应保持的概念区分

| 概念 | 当前可见表达 | 后续验收不变量 |
| --- | --- | --- |
| 种子与分身 | 想法可以有独立位置的呈现，同一概念内容共享 | 不把分身误作新的论证内容；保留来源与当前位置关系。 |
| 极性两端 | 「换观察位置，看见两端」；两端都能继续推演正反 | 负向坐标不等于辩证的「反」，正向坐标不代表更正确。 |
| 正／反 | 「推进判断，检验前提」 | 避免把反变成机械否定，保留当前母题与观察入口。 |
| 合 | 「继续展开」「展开来源」；可以暂不融合 | 合不覆盖来源，不等于完成答案；仍可继续追问、正反与极性。 |
| 乔哈里 | 由用户选择区域，未知留作问题，展开带假设标记 | 不把坐标选择当成用户或他人心理状态的事实依据。 |
| 空间视角与思考入口 | 面板区分「下一次生成」与「只转动视角」 | 复位镜头不改维度；改维度不重写旧种子的历史框架。 |

## 合并后的优先事项

### F-01 · P2 · 维度编辑的思考成果会静默丢失

双端把名称「尺度」改为「临时未保存名称」，切到观察再回编辑，名称恢复为「尺度」，没有提示。普通关闭也会卸载局部草稿。问题在于观察、关闭与显式取消承担了相同的丢弃副作用。

建议保留当前工作区的未保存编辑稿，明确保存后才用于生成，显式取消才放弃。验收须覆盖观察往返、关闭重开、取消、保存与切换工作区，不能串草稿，也不能暗中应用未保存维度。

证据：[修改时](evidence/fresh/mobile-390-dimension-unsaved.png)、[往返后](evidence/fresh/mobile-390-dimension-after-tab-roundtrip.png)。对应 **L-02 / E-01**。

### F-02 · P2 · 移动端平移后缺少可见的完整复位

主线程在 390px 触摸视口连续平移三次，pan 从 `(0,0)` 变为 `(-840,-210)`，种子全部离开画面。「复位三维视角」不可见；点「从前方观察」和「按已有角度归位」后，pan 仍为 `(-840,-210)`。内容没有丢失，恢复路径却不对等。

建议让既有复位动作在移动端可达，恢复临时 pan、zoom 与旋转，不重排用户保存的种子位置，也不改变思考框架。无需增加卡片或一排常驻工具。

证据：[平移后的舞台](evidence/fresh/mobile-390-panned-stage.png)、[归位动作后](evidence/fresh/mobile-390-panned-after-arrange.png)、[数值记录](evidence/fresh/observations.json)。对应 **L-01**。

### F-03 · P2 · 刷新保留了内容，没有接回阅读位置

双端在长文 `scrollTop=650` 时刷新，原聚焦节点仍保留，但阅读已关闭；重新开读后位置为 0。这里不是图谱或正文丢失，而是读者必须重新找回对象与段落。

建议按工作区保留阅读对象与段落锚点；可以直接恢复阅读，也可以让既有上下文的一次动作回到原段落。主动关闭后应保持关闭，换宽度优先恢复段落，切工作区不能串读位，合的正文同样适用。

证据：[刷新前](evidence/fresh/desktop-reading-before-refresh.png)、[刷新后](evidence/fresh/desktop-reading-after-refresh.png)、[重开读位记录](evidence/fresh/observations.json)。对应 **E-02**。P2 是连续阅读目标下的 UX 裁定，现有图谱持久化本身仍正常。

### F-04 · P2 · 错误恢复提示包含网页用户无法执行的操作

受控过载状态建议「切换到其他模型服务」，但网页没有该入口；认证、连接失败分支还会要求用户检查服务端密钥或 baseURL。当前可用的操作是保留文字、重试上次请求、继续写或先记下。

建议让主要恢复说明与这些真实能力一致，技术诊断留给部署者。重试上次与提交当前草稿也应让触摸用户直接看懂，保留既有草稿保护，不为此新增模型配置区。

证据：[受控错误状态](evidence/baseline/mobile-failure-retry.png)、[更多菜单](evidence/fresh/mobile-390-more-menu.png)。对应 **E-03**。本轮没有制造真实供应商故障；截图是受控响应，错误映射由当前源码确认。

### F-05 · P3 · 搜索无匹配被说成没有种子

已有其他种子时，输入不匹配的查询仍显示「还没有可组合的种子」，引导用户去新写或裂变。应区分真正没有对象与关键词无匹配，并允许就地清空查询，不发模型请求。

证据：[移动搜索空态](evidence/fresh/mobile-390-combine-no-search-results.png)。对应 **L-03 / E-04**。Lama 定为 P3、Emil 定为 P2；主线程合并为 P3，因为当前仍可直接清空输入恢复，没有内容丢失或操作阻断。

### F-06 · P3 · 高频键盘阅读仍重放 340ms 入场

键盘开读后焦点正确到达标题，同时仍运行 340ms 入场动画。桌面单击另有 260ms 双击识别窗口；这两个源码阶段不等于本轮测得的全设备端到端延迟，更不能说界面期间完全不能操作。

建议先让键盘开读稳定呈现，指针保留更轻、更短的来源关联，再观察反复阅读的节奏。保护焦点、读位和减弱动态效果，不取消现有双击快捷操作，也不把软糯感等同于增加等待。

证据：[动画与焦点记录](evidence/fresh/observations.json)。对应 **E-05**，行为已证实，主观影响仍是启发式判断。

## 单独保留的体验假设

- **组合候选的动作预期（L-04）。** 短标题点选会直接开始合成，这一行为符合当前快捷流程。尚无真实误触数据，未计入上述四个已确认 P2。可测试轻量动作说明或核对正文的路径，不建议默认加回二次确认。
- **阅读前先出现两个展开入口（L-05）。** 它可能让初访者过早分叉，也可能恰好帮助熟练者继续思考。应观察用户能否理解当前内容、区分两种展开，再决定是否调整阅读顺序或视觉权重，不应仅凭截图隐藏快捷操作。

**未证实显著选句跳位。** 桌面与移动的中段 DOM Range 选句都让同一句下移约 15.5px，仍保持可见；浏览器同时调整了 `scrollTop`。这不足以认定阅读被甩离原句，未列为修复项。该检查没有覆盖真实手指拖选和真实软键盘。

## 方法、范围与后续验收

本轮只读审阅产品，新增文件仅在本审阅目录。两份独立报告使用源码、实际查看的同日公网流程截图；主线程另在全新 Chromium 上下文采集桌面 1440×900、移动触摸 390×844 的首访、设置、长文、搜索与平移行为。合成花园数据只用于压力场景，禁止本轮捕获过程发模型 POST，未读取或清理用户原有工作区。初次取证脚本的等待错误和一次连接关闭已在补充采集中排除，未当成产品 finding。

复用证据中的 `live` 是先前同日部署验收的真实模型流程；等待、错误、拖拽专项是受控状态。它们是现有版本的证据，不是两位审阅者分别重跑了全部交互。本轮没有重新测量 iPhone/Android 真机热机、真实软键盘、深色模式、屏幕阅读器或真人心流。

后续修改仍应保留无卡片、sketch1638178 低饱和软糯材质、桌面 TSL 自动、移动原版、手动切换与自动回退。用同一条路径复验：初访 → 想法 → 阅读 → 选句追问 → 极性两端 → 正反 → 合 → 刷新 → 从合继续；同时加入四项 P2 的恢复场景。真人任务的观察问题是：当前在看什么、下一步对哪个对象生效、如何回到刚才的位置、新理解和来源有什么关系。
