# Anicca 浅色液态前端接入计划

日期：2026-10-01
状态：D1–D4 已确认，仓库内产品接入与自动化验收已完成；真实 Provider 与微信 iOS/Android H5 真机仍待外部验证。

> 后续已确认修订（2026-10-01）：用户要求减少界面干扰和卡顿，并明确任意两颗不同 seed 可合、每颗 seed 可直接裂变。以下原 D1 / D2 的“必须续问”“同母题一正一反”约束已被此修订替代。当前实现以新规则为准：`seed → 正/反`；补充文字仍可走 `seed → user → 正/反`；两来源可同角色、跨母题，也可包含想法或合。API 使用带真实角色的 `sources`，保留旧请求格式兼容；图继续保存双来源，不强造共同母题。界面只常驻舞台与单输入框，其他能力按需打开。舞台限 8 颗是绘制预算，不裁剪历史。本文下方旧阶段记录保留作历史说明。

## 1. 目标与已确认方向

2026-10-01 后续心流修订已获用户批准并要求 commit/push：取消鼠标跟随球；单击就地阅读，桌面双击直接裂变；拖拽靠近后短暂停留，松手直接合成，取消二次确认；等待时允许阅读和写下一段，结果不抢焦点；已有种子保持位置，新种子在来源附近寻找空位。下述原固定侧栏/底栏和松手后确认的记录由此修订替代。

用户提供的 anicca 前端核心源码已归档至 [`reference/anicca-liquid-frontend`](../../../reference/anicca-liquid-frontend/README.md)。后续接入以该仓库内路径为来源，重点完成正反合、裂变，同时考虑移动端和未来微信适配。用户已明确：现有前端可以作为备选分支。

本计划按以下方向组织后续工作：

- 新主线采用参考项目的浅色流动背景、半透明液态种子、留白和底部输入，重新组织 `/dialogue` 界面。
- 当前深色珍珠球体、谱系侧栏与详情面板版本进入备选分支，不再约束新主线的页面布局和材质方向。
- 保留现有真实正反合 API、图谱语义、上下文、工作区和历史数据，不用视觉原型的演示逻辑替换业务能力。
- 手机端作为主线验收对象；微信网页适配与未来原生小程序的技术边界分别设计。
- 分阶段交付不减少最终功能：输入、阅读正反、合成、继续裂变、历史回看、恢复工作区必须形成完整闭环。

初始授权范围为归档核心参考源码、更新来源地址和编写计划。用户随后批准实施、任意种子组合与直接裂变、恢复参考软体观感，并授权修复经核实的问题后提交推送。本次始终在现有主线程和工作空间推进，没有新增 agent 或 worktree。

## 4. 目标架构与文件责任

继续使用现有 Next.js / React 工程。参考项目使用 Vite、React 19 和 Tailwind 3，当前工程使用 Next.js、React 18 和 Tailwind 4；只迁移实际需要的页面与视觉源码，不复制整份 package.json、路由或无关 UI 模板依赖。

```text
用户操作（点选 / 输入 / 拖动 / 合成）
                  ↓
DialogueController：目标、请求、上下文、错误与工作区
                  ↓
DialecticApi → 现有 /api/branches、/api/synthesis
                  ↓ 成功且请求仍有效
BranchGraphStore → 工作区持久化
                  ↓
deriveDialogueView → SceneProjection → 新 LiquidStage + 阅读/输入/历史 UI
                                         ↓
                              renderer：材质、液桥、动画
```

名称为建议，以实际拆分保持最少重复职责。

| 模块/文件 | 修改责任 | 关键接口或约束 |
| --- | --- | --- |
| `src/components/dialogue/DialogueShell.tsx` | 接线与页面组合，逐步抽出业务用例 | 不重新实现一套图谱或请求保护 |
| `src/features/dialectic/controller.ts`（新增） | 输入、续问、合成、取消、重试与结果归属 | 必要时用单独 React hook 订阅；核心用例不依赖 DOM |
| `src/features/dialectic/api.ts`（新增） | typed 请求适配 | `generateBranches`、`generateSynthesis`；支持取消，统一错误 |
| `src/store/branchGraph.ts`、`src/types/anicca.ts` | 现有图语义 | `createUserNode / createChildUserNode / createAssistantPair / createSynthesisAssistant` |
| `src/features/dialectic/viewModel.ts` | 焦点、路径、可用动作 | 保持合的 lineage 与 sources 区分 |
| `src/features/dialectic/sceneProjection.ts`（新增） | 当前局部图变成可见场景 | 稳定 nodeId、角色、标签、位置与布局边界；不读取 DOM |
| `src/components/dialogue/liquid/*`（新增） | 新舞台、材质与动画 | `mount / resize / render / dispose`，只消费场景快照 |
| `src/features/dialectic/gestures.ts`（新增） | 点按、拖动、候选合成与取消 | 输出 select / move / proposeSynthesis；不能自己写 graph |
| 现有 Composer / ConversationPanel / BranchSidebar | 改造为输入、按需阅读与历史入口 | 保留工作区、圆桌和画作视角可达性 |
| `src/lib/persist/*` + 平台适配边界 | 复用 registry 与 snapshot；隔离平台访问 | Web 存储实现继续工作，未来再接小程序实现 |
| `src/app/dialogue/page.tsx` | 新主线入口 | 最终 `/` 与 `/dialogue` 导向新界面 |

保留现有接口结构：

- `POST /api/branches`：`requestId, userText, contextMessages` → `requestId, thesis, antithesis`。
- `POST /api/synthesis`：`requestId, rootInput, thesis, antithesis, contextMessages` → `requestId, synthesis`。
- 每个生成内容继续使用 `text / label / summary` 等现有字段，画布使用短标签，阅读面板使用正文。
- 直接裂变与补充文字续问均复用 branches；synthesis 新增 `sources` 双来源契约并兼容旧格式。自动多角度未纳入本轮契约。
- `requestId / workspaceSessionId / focusSnapshotId` 继续负责迟到响应和焦点保护；取消网络只是补充，不能代替结果归属检查。
- 物理速度、弹性和碰撞留在运行时；只保存稳定布局、焦点和续问目标。桌面与手机布局分别恢复。

## 5. 交互与视觉契约

### 5.1 输入 → 正反

空场只保留品牌、轻提示、底部输入与工作区入口。发送后以临时母题种子呼吸表示等待，不用复制的文字假装模型已经生成。API 成功并通过归属检查后写图，再播放分裂动画；失败保留草稿和目标，提供重试。

正反保持可辨识的相对位置与文字标记，颜色不能作为唯一依据。母题成为可回访的路径锚点。移除原型的 40 字业务截断，按现有 API 上限校验输入。

### 5.2 阅读与比较

点选种子打开正文，选中期间收敛漂移；气泡上只显示 label 和角色，正文不持续晃动。桌面按需展开阅读面板；手机底部面板可展开、收起和独立滚动。正反之间可直接切换，保留阅读位置与母题提示。

参考视觉应保留浅色、透明、柔软和留白，不退回当前硬高光球体、密集边框和三栏信息堆叠。背景与球体不能吞没正文；提示、占位与正文分别检查对比度。

### 5.3 合

- 明确按钮是基础入口；拖拽靠近只产生候选预览，松手后仍需显式确认。
- 只接受同母题的一正一反，不接受任意碰撞、同角色或跨母题直接合成。
- 请求期间保留来源；成功新增合，来源可缩小或收进路径，但不删除。
- 保存 `sourceNodeIds` 和 `lineageParentId`，正文面板可查看双来源并继续追问。
- 失败、取消、pointercancel、窗口失焦不得落下半成品；已有合提供查看记录，避免重复误触。

### 5.4 裂变

按已确认的 D1，用户选中任意正、反、合，点“继续裂变”，输入区明确显示“基于哪个观点”。提交下一问后形成 `assistant → user → 正/反`。父节点保留，两个子节点沿液桥长出，祖先退为路径。

舞台主要显示当前局部；点击祖先可返回。可见种子上限是渲染预算，不是图历史上限。双击、长按、捏合都不能是唯一入口。

自动多角度裂变如后续纳入，需另行新增内容生成、错误恢复和验收契约；当前画作视角模板不得替代。

### 5.5 历史与其他能力

保留创建/切换/重命名工作区、导入导出、旧数据恢复、画作视角与圆桌。常驻舞台之外的入口收进菜单或阅读面板，不直接删除功能。不允许直接覆写已被后代引用的模型观点；用户修订通过新补充或分支留下历史。

## 6. 移动端与微信适配

### 6.1 移动 Web 必需项

- 全屏舞台、简洁顶部、始终可达的输入；谱系按需展开，不堆在舞台下面。
- 布局使用实际可用矩形，扣除安全区、顶部、输入、阅读面板和软键盘；不能继续只用 window.innerWidth/innerHeight。
- 处理动态视口与键盘弹起/收起；输入聚焦时收拢舞台，发送不被键盘挡住。
- 主要触控目标至少 44×44 CSS px；设置拖动阈值和取消路径，区分正文滚动、文字选择与舞台手势。
- 按设备和帧耗时限制可见曲面、像素比与动画强度；后台暂停实际模拟和渲染，退出释放资源。
- WebGL 不可用、context lost、reduced-motion 时仍可阅读、选择、提交、合成和回看。

### 6.2 微信的三条路径

| 路径 | 复用范围 | 本计划处理方式 |
| --- | --- | --- |
| 微信内 H5 | Web UI、业务与后端 | 建议作为近期适配对象，列入独立真机验收；D4 确认后执行 |
| 小程序 web-view | 承载 H5 | 条件性选择，先核对主体资格、业务域名、通信与分享限制，不承诺直接套壳发布 |
| 原生小程序 | 图模型、业务契约、布局算法、后端 | 预留平台边界；页面、触摸、存储、网络、Canvas 生命周期另行适配 |

不为未来可能的小程序现在就重建 monorepo 或迁移跨端框架。纯业务层避免 window/document，平台能力通过适配器提供；原生小程序选型等目标明确后再定。local-first 不等于跨设备同步，云同步与分享需另行定义。

微信官方维护的 [Canvas 类型声明](https://github.com/wechat-miniprogram/api-typings/blob/master/types/wx/lib.wx.canvas.d.ts) 包含 WebGL2 接口，但不能据此证明 Shader Park 运行时与目标设备完全兼容。本轮官方 web-view 页面未能读取，具体平台准入条件未核实；实施时重新核对并以真机验证为准。

## 8. 验收与验证方法

| 类别 | 必须通过的场景 |
| --- | --- |
| 正反合 | 输入调用生成接口；任意两颗不同种子可合；跨母题、同角色与合再合保留真实角色和双来源；重复来源被阻止 |
| 裂变 | 任意种子可直接裂变，也可补充文字；下一轮父节点、来源与上下文正确 |
| 请求可靠性 | 慢响应、失败重试、重复触发、取消、切工作区、切焦点不会重复写入、错写或抢焦点 |
| 数据兼容 | 旧工作区可恢复；刷新、导出再导入后图、来源、焦点、续问目标与布局正确 |
| 长会话 | 超过视觉槽位仍可访问完整历史，不删除不可见节点 |
| 移动布局 | 360/390/430 宽度、平板与桌面；软键盘、旋转、安全区和长正文不会遮挡主要操作 |
| 微信 | 如纳入 D4，分别记录 iOS/Android 设备、系统、微信版本、键盘、返回恢复与 WebGL 结果 |
| 可访问性 | 主要流程支持键盘与有名称的语义按钮；颜色非唯一信息；面板焦点进入/返回正确；测量文本对比度 |
| 渲染可靠性 | WebGL 禁用/context lost/reduced-motion 可完成流程；反复进入退出无累计 rAF、监听器或 GPU 资源 |
| 视觉 | 对照参考截图检查色场、透明度、柔边、留白、文字和关键状态；没有用旧材质替代新设计 |

代码验证沿用仓库门禁：

```bash
npm run lint
npm run typecheck
npm run typecheck:test
npm test
npm run build
npm run test:visual-dialogue
```

最后一项用于必要视觉回归，需更新旧界面的布局断言与证据。测试重点是语义、生命周期、错误和数据恢复；不为纯样式微调新增镜像实现的测试。任何必需验证失败须先定位修复；真机或外部条件缺失时记录具体阻塞。

### 8.3 心流修订实施（2026-10-01）

- Shader Park 移除鼠标坐标输入和跟随球；普通鼠标移动不再唤醒交互高帧率，种子按压、弹性和靠近液桥保留。
- 鼠标单击与双击区分；双击直接裂变。触屏 350ms 长按进入拖动，两颗有效来源靠近后停留 320ms 显示“松手合成”；释放才请求，快速经过、移开、pointercancel、Escape、失焦均不触发。生成期间禁止重复请求。
- `SeedReadingCard` 依据来源按钮、visual viewport 与 composer 的实际矩形定位；尺寸变化时重新约束，支持正文滚动、点击外部关闭和 Escape 返回来源。正文样式显式解除旧面板的绝对定位。
- 提交保存原文本、目标和草稿版本；等待时保持输入可编辑。成功仅清除未改动的已提交草稿；重试仍提交原内容，保留后来草稿。用户已阅读另一颗或继续输入时，结果不改变其当前上下文，也不自动打开阅读卡片。
- 宽屏/窄屏分别保存初始与拖动位置。新增种子只寻找自己的位置，优先靠近单来源或双来源中心，已有种子不因数量变化重新排布；刷新后复用保存位置。
- `npm run check` 通过：51 个文件、336 项测试；ESLint 为 0 error、19 条既有 warning。生产构建通过。测试覆盖快速经过、移开、取消、Escape、失焦、双击不误读、草稿版本及原操作重试。
- 系统 Chrome 的 9 组视口与 5 项专项全通过；验证卡片可见正文位于卡片内且不遮住 composer、旧种子位置不变、着色器无跟随球、桌面双击只发一次请求、长按停留后松手合成、后来草稿不丢失和取消后晚到结果不落图。汇总与截图：`/tmp/anicca-flow-final/dialogue/summary.json`。桌面 1440×980 的 4 秒采样为 88 次绘制、0 次布局读取，rAF 间隔 p95 为 16.8ms，仅代表本机本次采样。真实 Provider 与微信真机仍沿用上节未验证范围。
